# 浏览器内实时设计设置

页面右下角的「设计系统 · 实时设置」提供同一站点的设计系统入口和本机外观偏好。首页、编辑器、组件库、Token 审计、资产库、动效库以及单组件预览均带有入口。

- 首页：标题字号、平台标题显示、光流与漂浮、自动旋转。
- 首页与编辑器：亮度、主灯、内置平台玻璃浓度、发光。
- 使用对应 CSS 变量的 UI：背景、卡片底色、强调色、正文颜色、卡片和按钮圆角。正文字号控件仅在实际消费该变量的设计规则页、组件库及组件预览显示。原有固定颜色和 3D 材质不会被 UI 颜色设置重写。
- 修改立即应用；自动保存到当前浏览器的当前部署目录。另一标签页会同步，重新打开会恢复。无法保存时页面会提示导出。
- 支持恢复默认和 JSON 导入/导出；不支持的版本、未知属性、越界值及无效颜色会被拒绝，不覆盖现有设置。
- 尊重系统的减少动态效果偏好；用户可明确开启光流。拖拽首页时自动旋转会停止，旧控制按钮与新面板保持同步。

此功能不请求模型、无 API key、无远程保存接口。每次拖动、切换、保存或导入均在浏览器执行，不消耗 AI token。开发功能时的对话用量不在此承诺范围内。

## 存储与源码边界

偏好是运行时覆盖，不是真源迁移。Token 审计卡片继续显示代码中的默认数值；导出的设置文件是浏览器偏好，不是布局 JSON，也不会自动修改 GitHub 上的源码或其他人的默认外观。恢复设置不会清除编辑器中的模型、上传文件或布局。

同一部署下的 `preview/` 与根页面共享设置，其他项目和各 `pr-preview/<candidate>/` 目录彼此隔离。线上与 localhost 为不同来源，不共享本地存储。跨浏览器可手动导出、导入。

构建最后一步 `source/build-settings.mjs` 将 UI 脚本和 CSS 内联，保留首页原有 CSP，且不会引入 CDN、AI 服务或新依赖。`source/settings/schema.js` 定义允许的设置及校验；`panel.js` 处理 UI/存储，`scene.js` 将设置应用到真实 Three.js 场景。设置面板 CSS 独立于现有 28 个组件的原始样式审计；现有审计数字描述原先的组件样式文件，并非新增面板的 CSS 总计。首页现在也内联了同一份默认变量，其原有硬编码 CSS 尚未全面迁移。

## 回归检查

在 `source/` 中运行 `npm run build`、`npm run test:settings`、`npm run check:docs`；存储隔离回归为 `node --test review/storage-scope.test.mjs`。

通过本机静态 HTTP 服务打开构建后的页面，在真实浏览器检查：
1. 首页亮度、平台玻璃、字号、标签、动效能即时变化。
2. 刷新保留；打开 Token 页改颜色/圆角，另一标签页同步。
3. 有效导入生效；无效导入保持旧值；恢复默认同时作用到打开的页面。
4. 编辑器的真实渲染响应 3D 设置；面板键盘不触发编辑器的模型移动快捷键。
5. 390px 宽度下面板不越界，底部按钮可见；Tab/Shift+Tab 在面板首尾循环；Escape 在焦点移到页面后仍能关闭并将焦点还给入口。
6. 检查控制台错误，打开面板和改变设置不应触发模型请求。

发布前按仓库 `.agents/skills/verify.md` 对最终候选执行 pre-PR runtime verification。合并后的 GitHub Pages 发布还需绑定最终提交，在公开页面重新验证设置和刷新恢复；功能说明本身不替代部署验收记录。
